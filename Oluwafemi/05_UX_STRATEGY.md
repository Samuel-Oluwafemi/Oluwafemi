# Oluwafemi — UX Strategy

## Core UX Goal

The portfolio should move visitors through this sequence:

**Attention → Understanding → Proof → Trust → Relevance → Action**

---

# 01 — Navbar

## Purpose

Help users navigate without distracting from the portfolio.

## UX goal

Make the portfolio feel easy to explore.

Navigation:

Work  
Services  
About  
Contact

CTA:

Let's build

---

# 02 — Hero

## Purpose

Answer:

"What does this person do?"

within seconds.

## Conversion goal

Move qualified visitors toward:

**View my work**

or

**Let's work together**

The hero should communicate:

- role
- value
- specialization
- confidence

Do not make visitors decode the message.

---

# 03 — Selected Work

## Purpose

Proof.

This is the most important section after the hero.

Instead of saying:

"I'm a good developer."

Show:

"Here are things I've built."

## Conversion goal

Create curiosity and credibility.

Each project should answer:

- What is it?
- What did Samuel do?
- Why does it matter?
- What technologies were involved?

---

# 04 — Services

## Purpose

Help business owners recognize themselves.

A visitor should be able to say:

"That's what I need."

Services should be framed around outcomes rather than technology.

Bad:

"React development"

Better:

"Booking experiences"

---

# 05 — Process

## Purpose

Reduce uncertainty.

Potential clients often wonder:

"What happens if I contact him?"

The process should show:

Understand → Structure → Design → Build → Test → Ship

## Conversion effect

Makes Samuel feel organized and professional.

---

# 06 — About

## Purpose

Human connection.

The visitor has already seen the work.

Now explain the person behind it.

The About section should answer:

- Where did he start?
- Why does he build?
- What does he care about?
- Where is he going?

Do not turn it into a long autobiography.

---

# 07 — Tech Stack

## Purpose

Technical credibility.

Do not make this the centerpiece.

Clients usually care about outcomes.

Recruiters/developers can inspect the stack.

---

# 08 — Client CTA

## Purpose

Convert visitors.

This is where the portfolio shifts from:

"Look at my work"

to:

"Let's talk about yours."

Headline:

Have something worth building?

CTA:

Start a conversation

---

# 09 — Contact

## Purpose

Remove friction.

Do not make users fill out a 15-field form.

Use:

- name
- email
- project type
- message

---

# CTA STRATEGY

Primary CTA:

**Let's build**

Secondary:

**View my work**

Contact CTA:

**Start a conversation**

Avoid constantly changing CTA wording.

Consistency builds recognition.

---

# CONVERSION PRINCIPLE

The portfolio should sell through evidence.

Do not aggressively say:

"I'm the best."

Instead show:

- strong work
- clear thinking
- good UX
- clean design
- technical ability
- business awareness

The visitor reaches the conclusion themselves.

---

# CLIENT-SPECIFIC UX

Business owners should be able to find:

1. What Samuel builds
2. Examples
3. How he works
4. How to contact him

within a short scroll.

---

# RECRUITER UX

Recruiters should be able to find:

- skills
- stack
- projects
- GitHub
- LinkedIn
- contact

without searching.

---

# MOBILE UX

Mobile users should receive the same story.

Prioritize:

Hero → Work → Services → About → CTA

Avoid overwhelming mobile visitors with excessive animation or huge text blocks.

---

# TRUST

Trust should come from:

- actual projects
- transparent project labels
- clear process
- honest descriptions
- polished execution

Never invent testimonials or metrics.
