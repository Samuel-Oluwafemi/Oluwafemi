# Oluwafemi — Image Direction

## Philosophy

The portfolio should be visually driven by the actual work.

Do not fill the portfolio with generic developer stock images.

The projects are the visual identity.

---

# HERO IMAGE DIRECTION

The hero should NOT use a generic:

- laptop image
- coding desk
- programmer stock photo
- random 3D illustration

Instead create an abstract developer studio composition.

Possible elements:

- project thumbnails
- UI fragments
- subtle browser windows
- build metadata
- cursor
- small terminal-inspired labels
- project status
- O/X monogram
- subtle grid
- dark background

The composition should feel like a digital workspace.

---

# PROJECT IMAGES

Every featured project must have a strong visual.

Use:

- website screenshots
- browser mockups
- responsive previews
- mobile + desktop compositions
- cropped UI details
- real project imagery

Avoid excessive device mockups.

The website itself should be the visual hero.

# PROJECT CARD IMAGE RULE

Project card images should occupy a large portion of the card.

Do not hide the screenshot inside a tiny card.

The visitor should be able to understand what was built before reading the description.

---

# IMAGE TREATMENT

Use:

`rounded-2xl`

Subtle border:

`border border-slate-800`

Hover:

`group-hover:scale-[1.03]`

Use subtle image scaling.

---

# MOBILE IMAGE RULE

Images must remain visually strong on mobile.

Do not crop the most important UI content.

Use appropriate aspect ratios.

---

# PERFORMANCE

Optimize images.

Prefer:

- WebP
- AVIF where practical

Use lazy loading below the fold.

Do not load unnecessarily huge images.

---

# IMPORTANT

Never invent project screenshots.

Never use fake analytics screenshots.

Never create fake client results.

If a project is a concept, visually label it:

`CONCEPT`

If it is unfinished:

`IN PROGRESS`
