# OluwafemiX — Developer Portfolio

## Project Overview

Build a premium personal portfolio website for **Samuel Oluwafemi**, publicly known as **OluwafemiX**.

This is not a generic developer portfolio.

The website should feel like a modern digital studio belonging to a developer who understands:

- frontend development
- modern UI design
- UX
- conversion-focused websites
- business goals
- product thinking
- client acquisition
- shipping real digital experiences

The portfolio should communicate that Samuel doesn't simply "write code."

He studies a problem, thinks about the user journey, designs an experience, builds it and ships it.

---

Primary positioning:

# Brand Personality

The website should feel:

- confident
- modern
- ambitious
- intelligent
- calm
- technical
- creative
- human
- slightly experimental

Avoid:

- generic developer portfolio layouts
- excessive gradients
- childish animations
- "Hello World" aesthetics
- fake seniority
- corporate language
- excessive glassmorphism
- excessive neon
- template-looking sections

---

# Visual Direction

Create a:

**Dark Editorial Developer Studio**

The visual language should combine:

- premium editorial typography
- dark software interfaces
- subtle technical details
- large typography
- strong project imagery
- structured layouts
- refined spacing
- minimal but meaningful motion

Think:

**creative studio × modern SaaS × developer workspace × editorial magazine**

The design should feel expensive because of:

- typography
- spacing
- composition
- hierarchy
- imagery
- restraint

Not because of visual effects.

# Technical Direction

Use:

- React
- Vite
- TypeScript where practical
- Tailwind CSS
- React Router
- Framer Motion
- Lucide React

Use reusable components.

Keep the architecture clean without over-engineering.

---

# Important AI Development Rule

AI-assisted development is allowed and encouraged as part of the workflow.

However, generated code must be reviewed.

Verify:

- state
- routing
- accessibility
- responsiveness
- API calls
- forms
- error handling
- performance
- component structure

The goal is not to generate the most code.

The goal is to ship a polished product that Samuel understands.

---

# Final Quality Standard

The finished portfolio should feel like something a professional frontend developer could confidently send to a business owner and say:

> "This is what I can build for you."

It should not feel like a student portfolio.
